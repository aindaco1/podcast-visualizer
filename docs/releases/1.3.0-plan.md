# Podcast Visualizer 1.3.0 execution plan

Status: source implementation completed and locally verified on 2026-09-01.
The thirteen product decisions below define the 1.3.0 scope. Signing,
notarization, installed-app acceptance, and the 1.2.4 to 1.3.0 updater hop
remain separate release gates.

Proposed branch: `release/1.3.0`

This document is the approved scope, sequencing, and release gate for Podcast
Visualizer 1.3.0. It supersedes the earlier proposal to add wholly new dialogue
at an empty timestamp.

The release instead improves the existing transcript-review workflow in three
connected areas:

1. split one long transcript cue into two timed cues and merge adjacent cues;
2. evaluate local Parakeet recognition confidence for each cue and filter the
   transcript by confidence tier; and
3. commit valid speaker-name changes on Return or focus loss without requiring
   the Rename button.

The bottom waveform is not part of 1.3.0. Existing local-first, immutable-stage,
review, alignment, render, updater, and release contracts remain in force.

## Locked product decisions

- Split uses the text insertion point for the word boundary and the audio
  playhead for the timestamp.
- The UI shows confidence tiers only. It does not expose the raw model score.
- Each cue has an explicit Checked control, separate from model confidence.
- The native app is the complete 1.3.0 experience. Browser Fallback must remain
  compatible with resulting cue data but does not need feature or interaction
  parity in this release.
- Native merging offers adjacent Merge Previous and Merge Next actions.
  Multi-row selection remains out of scope.
- Remove the Rename button after Return, focus-loss, and speaker-switch commits
  pass automated acceptance. Manual installed-app acceptance remains a separate
  release gate.
- Checked state survives Save, quit, and relaunch for the current working
  review, then resets when a new edit begins from an approved revision. It is
  not approved transcript content.
- Checking remains an explicit reviewer action. Editing a cue does not
  automatically mark the full cue Checked.
- Confidence calibration may use existing rights-cleared, human-reviewed local
  projects. Private evaluation media and transcripts never leave the Mac and
  never enter Git or CI.
- Split remains disabled when there is no valid text insertion point and guides
  the reviewer to place the caret between words. It never guesses the text
  boundary from the playhead alone.
- Useful, stable confidence tiers are a 1.3.0 release gate. If calibration does
  not support them, the entire release waits; arbitrary tiers do not ship and
  confidence is not silently moved to 1.3.1.
- Confidence calibration judges spoken-word recognition only. Capitalization,
  punctuation, formatting, speaker assignment, and timing remain separate
  editorial signals that the Parakeet token score does not claim to evaluate.
- Tier tuning prioritizes catching spoken-word errors. Ultra Low and Low may
  conservatively include correct cues rather than allowing more erroneous cues
  to appear in Medium or High.

## Outcome

A reviewer can listen to a long cue, put the audio playhead at the desired time,
split the existing text at a word boundary, and later merge adjacent cues when
the automatic segmentation was too aggressive. Split and merge preserve all
words and the outside timing bounds; neither operation invents dialogue.

Every transcript cue displays an honest, local recognition-confidence tier.
The reviewer can show any combination of Ultra Low, Low, Medium, and High cues
in chronological order, optionally combined with the existing speaker filter,
so the least reliable recognition can be checked first.

Renaming a speaker commits on Return and on leaving the name field. The change
still enters the review's dirty and Undo state and is persisted only through the
existing Save/Approve workflow.

## Non-negotiable product rules

- Confidence is an advisory triage signal, not a correctness guarantee.
- No percentage or raw recognition score is displayed. The first release uses
  tiers only.
- Confidence is derived only from the existing on-device Parakeet output. No
  transcript, token, audio, review data, or model input leaves the Mac.
- Split and merge preserve transcript words. Text correction remains an
  explicit human edit.
- Existing cues, approved transcript revisions, alignments, scenes, renders,
  exports, and source media are never silently overwritten or deleted.
- Approval still creates an immutable content-addressed revision and retains
  its parent revision.
- A new active transcript invalidates downstream reuse for the workflow but
  does not remove prior generated evidence.

## Workstream 1: one cue-structure editing contract

### Split

Add a pure split operation beside the existing `ReviewEditing.mergeNext`
operation. It accepts a stable cue ID, an integer playhead timestamp, and a
Unicode-safe text boundary.

A valid split must:

- target the cue that contains the playhead;
- keep at least the existing 150 ms safety margin on both sides of the split;
- divide text only at a grapheme- and word-safe boundary with non-empty text on
  both sides;
- preserve the source cue's start on the left and end on the right;
- use the playhead as the left end and right start;
- keep the source cue ID on the left and allocate the lowest unused bounded
  `cue_NNNNNN` identity for the right;
- copy speaker assignment and confirmation state to both children;
- preserve the ordered words exactly when the child texts are joined with the
  canonical single separator; and
- apply as one dirty-state and Undo operation.

The approved interaction uses both pieces of reviewer evidence: the audio
playhead sets the timestamp and the text insertion point sets the word boundary.
Without a valid insertion point between words, Split remains disabled and the
app explains how to enable it. The app never guesses or applies a text division
from the playhead alone.

The current browser fallback may retain its proportional split interaction for
1.3.0. It must continue to load, save, and approve structurally valid cues
created by the native app. Canonical cue validation, ID safety, word
preservation, persistence, and approval remain shared trust-boundary contracts;
browser interaction and Undo parity are not release requirements.

### Merge

Retain adjacent-cue merging and make it the inverse of the split contract where
possible:

- merge only chronological neighbors;
- keep the left cue ID and outside `[left.start, right.end)` bounds;
- join the two texts with one canonical separator without dropping or
  duplicating words;
- preserve confirmed speaker status only when both cues have the same confirmed
  speaker;
- otherwise retain the current fail-closed behavior: mark the merged cue
  unconfirmed and ambiguous so approval cannot silently pass it; and
- apply as one dirty-state and Undo operation.

The native app already exposes Merge Next. The implementation should add Split,
make the structural actions consistent and discoverable, and add Merge
Previous. Multi-selection and non-adjacent merges are out of scope.

### DRY ownership

- `PodcastVisualizerCore.ReviewEditing` owns the pure native in-memory split and
  merge policy used by counts, button enablement, store mutation, and Undo.
- `TranscriptReviewStore` coordinates playhead, selection, dirty state, filters,
  stable row reconciliation, and status messages.
- Views present actions and validation; they do not implement cue mutation.
- JavaScript remains authoritative for untrusted edit validation,
  normalization, persistence, hashes, lineage, and approval.
- Generic normalization and confidence aggregation belong in
  `@dustwave/timed-text`; application interaction and release policy remain in
  this repository.

Duplicated validation at the Swift presentation boundary and JavaScript
persistence boundary is intentional fail-closed defense. Mutation rules and
threshold definitions must each have one owner and contract fixtures that both
boundaries accept.

## Workstream 2: recognition-confidence evidence

### Available source evidence

The existing private `analysis/speech.json` already contains:

- one overall Parakeet confidence value;
- timestamped Parakeet tokens with individual `0...1` confidence values; and
- timestamped words used to compile review cues.

The application currently validates those token confidences and then drops them
when grouping words into review cues. No new model run or network service is
required. Speaker confidence remains separate diarization evidence and must not
be labeled as transcript confidence.

### Confidence policy

Add one versioned, deterministic timed-text confidence policy that:

1. associates each non-empty, bounded Parakeet token with its source cue by
   validated timing and source order;
2. aggregates the contributing token scores conservatively so one uncertain
   word is not hidden by a long high-confidence line;
3. records a bounded `0...1` source score plus one of `ultraLow`, `low`,
   `medium`, or `high`;
4. uses `unavailable` when valid legacy evidence cannot supply a score;
5. never includes token text in diagnostics or confidence-only reports; and
6. produces identical results for identical immutable speech evidence and cue
   bounds.

Do not choose thresholds by taste. Establish a calibration dataset by comparing
Parakeet token scores with actual human corrections on approved local material.
Measure at least tier population, correction rate by tier, false-negative rate,
and stability across short/long cues and different speakers. Select and version
fixed thresholds only after that evidence exists.

Calibration labels only spoken-word recognition errors. Ignore capitalization,
punctuation, formatting, speaker assignment, and timing differences when
judging the recognition tiers; those layers require their own evidence and must
not be folded into the Parakeet score.

The primary optimization goal is recall: cues with spoken-word errors should
rarely land in Medium or High. It is acceptable for conservative Ultra Low and
Low queues to include correct cues. The UI shows only the tier, without a
percent sign or raw model score. The underlying bounded score remains internal
recognition evidence used to derive and validate the versioned tier.

### Confidence through editing

Confidence describes the original local recognition evidence for the time
range, not the correctness of the current human-edited text.

- ordinary text edits retain the original source tier and add a visible Edited
  state rather than pretending the model rescored the correction;
- split children receive confidence derived from their respective source token
  ranges when that mapping is available;
- if a legacy cue lacks word-level provenance, both split children inherit the
  parent's tier conservatively;
- a merged cue receives the most conservative contributing tier, not a simple
  average that could hide a weak section;
- dialogue reflow on approval applies the same conservative merge rule; and
- manually structured legacy cues with no valid token coverage display
  Unavailable, never an invented score.

### Contract and compatibility strategy

Keep editable transcript content separate from read-only recognition evidence.
Do not trust a score submitted by a UI.

The preferred implementation is:

- add a versioned confidence compiler to `@dustwave/timed-text`;
- derive confidence from the immutable speech artifact at review-workspace load;
- expose a bounded, typed confidence record keyed by stable working cue ID;
- recompute or conservatively propagate evidence after split/merge;
- let the CLI revalidate/rederive submitted structural edits before saving or
  approving; and
- keep confidence out of alignment text, transcript content hashes, render
  dialogue, and user-editable fields.

If the workspace response must change, bump it once and retain decoding for
version three. Avoid changing edit, working-copy, or reviewed-transcript schemas
unless implementation proves the evidence cannot remain derived. Existing
projects must reopen without reanalysis; missing legacy evidence degrades to
Unavailable rather than rewriting immutable files.

## Workstream 3: confidence presentation and filtering

Each cue row shows a compact, accessible confidence label with text and color;
color alone cannot carry meaning. Keep speaker-review warnings visually and
semantically distinct.

Add confidence filters alongside the existing speaker filter:

- All Confidence;
- Ultra Low;
- Low;
- Medium;
- High; and
- Unavailable when present.

Allow multiple confidence tiers at once. Combine speaker and confidence filters
with AND semantics and keep the retained cues in chronological order; never
reorder the transcript by score. Show `visible of total` and tier counts so a
filtered empty state is understandable. Clearing filters restores the entire
transcript.

Find/Replace navigation, selected matches, cue seeking, Split, Merge, Undo,
Save, and approval must remain correct while filters hide rows. A stale action
from a removed or hidden row must remain a safe no-op.

Add an explicit Checked control to every cue. Checked state is separate from
immutable model confidence: listening to a line without changing its text can
still mark it checked, confidence never changes when it is checked, and Undo
restores the prior state. Add an Unchecked-only review toggle so verified cues
can leave the active review queue without changing the selected confidence
tiers. Editing a cue does not automatically check it.

Persist Checked state through Save, quit, and relaunch for the current working
review. Version the mutable working-copy schema once, retain backward decoding
with unchecked defaults, and exclude the state from approved transcript
content, hashes, alignment, and renders. Reset it when a new edit begins from an
approved revision.

Filtering 10,000 cues must remain a bounded in-memory pass with no model call,
disk scan, transcript-wide regular expression, or repeated sorting per row.

## Workstream 4: frictionless speaker renaming

The native name field currently calls the rename action on Return but also
shows a separate Rename button. Treat the reported friction as an interaction
and focus-management bug, not just a label change.

Use one `commitSpeakerRename` store operation for every trigger:

- Return commits a valid changed name;
- moving focus away commits a valid changed name;
- choosing a different speaker first commits the prior valid draft;
- whitespace-only, control-character, overlong, or otherwise invalid input does
  not mutate the speaker definition;
- invalid input reverts to the last valid display name with a concise recovery
  message; and
- one committed rename creates one Undo action and one dirty-state transition.

Do not write a working copy on every keystroke or blur. “Commit” changes the
in-memory review; the existing Save/Approve action remains the only persistence
path. Remove the Rename button only after all automatic commit paths pass
acceptance, leaving Return and ordinary focus movement as complete keyboard and
pointer interactions.

Browser Fallback does not need the revised rename interaction in 1.3.0. Its
submitted names must continue to pass the same bounded persistence validation;
native focus behavior and Undo parity are not release requirements.

## Automated acceptance

### Split and merge

- valid split at the beginning-side, middle, and ending-side safety boundaries;
- rejection at/outside cue bounds, inside the 150 ms margins, on an empty side,
  mid-grapheme, stale cue ID, invalid playhead, cue-cap exhaustion, and ID
  exhaustion;
- exact word preservation, chronological timing, stable left identity, safe
  right identity, and no mutation of unrelated cues;
- same-speaker and cross-speaker merges with correct confirmation state;
- split then merge round-trip where normalization permits;
- one-step Undo/Redo and safe retained callbacks after consecutive operations;
- Save/reload and immutable approval after split and merge;
- Browser Fallback can load, save, and approve the native operation results; and
- a 10,000-cue bounded-performance case.

### Confidence

- exact token-to-cue association at boundaries, pauses, and overlapping token
  edge cases;
- empty/control token rejection and bounded item/count/score validation;
- deterministic aggregation and tier thresholds at every boundary value;
- one weak token is not hidden by many strong tokens;
- split, merge, reflow, text-edit, and Unavailable behavior;
- speaker confidence cannot be surfaced as recognition confidence;
- no transcript/token text in diagnostics or evaluation summaries;
- legacy workspace/project compatibility without artifact mutation;
- speaker-plus-confidence filter composition, multi-tier selection, counts,
  empty state, and filter reset;
- explicit Checked toggling and Undo, Save/reload persistence, legacy unchecked
  defaults, reset for a new edit, and exclusion from transcript hashes/renders;
- text editing does not implicitly mark a cue Checked;
- search/navigation and structural edits while rows are filtered; and
- linear 10,000-cue filtering and confidence compilation baselines.

### Speaker renaming

- Return, focus loss, and speaker-switch commit the same normalized value;
- unchanged input is a no-op;
- invalid input restores the prior valid label without data loss;
- exactly one Undo action per committed name;
- dirty/save/reload/approve behavior remains unchanged;
- the Rename button is absent only after automatic commit acceptance passes;
  and
- the persistence validator accepts and rejects the same display-name fixtures
  regardless of client.

### Failure presentation

Every new user-visible failure must state the problem, recovery step, and what
was preserved. Regression-test the message contract. Examples include an
unsafe split position, confidence evidence unavailable, a rejected speaker
name, and a failed save after structural edits.

## Manual acceptance with local rights-cleared media

1. Split a genuinely long cue using a chosen text boundary and audio playhead;
   listen across the boundary, Undo/Redo it, Save, quit, relaunch, and confirm
   exact restoration.
2. Merge same-speaker neighbors, then merge different-speaker neighbors and
   confirm the latter cannot be approved until reassigned and confirmed.
3. Approve a split/merged revision and verify the parent transcript and all old
   downstream files remain byte-for-byte intact.
4. Compare cue tiers against the human-reviewed transcript; inspect every Ultra
   Low cue and a representative sample of the other tiers.
5. Filter Ultra Low + Low, combine that selection with one speaker, seek and
   edit only the visible cues, explicitly check verified cues, Save/relaunch,
   and confirm Unchecked-only review progress before clearing filters and
   verifying full chronology.
6. Split and merge while a confidence filter is active and confirm row identity,
   counts, confidence propagation, search, Undo, and approval.
7. Rename speakers with Return, click-away, and speaker switching; verify invalid
   input recovery and persistence after Save/relaunch.
8. Open the native-edited project in Browser Fallback and verify it can load,
   save, and approve the resulting valid cue structure without data loss.
9. Render representative opaque and alpha outputs and verify split/merge timing,
   dialogue text, speaker labels/colors, reflow, audio sync, and no confidence UI
   metadata in media outputs.
10. Force cancellation and save/approval failures; confirm all prior files and
    the last valid working state remain recoverable.

## Release gates

After source, calibration, performance, and signed-app acceptance:

- complete the existing signing, nested-code inventory, notarization, stapling,
  mounted-DMG, Gatekeeper, checksum, SBOM, provenance, size-budget, and signed
  appcast gates;
- verify the exact public assets from an empty download directory;
- perform a real installed `1.2.4 -> 1.3.0` Sparkle prompt, user-approved
  install, relaunch, and version check; and
- repeat split, merge, confidence filtering, rename-on-blur, Save, reopen, and
  approval in the installed signed application.

A green source suite does not prove confidence usefulness, real-media timing,
the signed app, public assets, or the updater hop.

## Explicitly out of scope

- wholly new dialogue in an empty timeline interval;
- non-spoken notes, markers, chapters, or overlay callouts;
- editing the numeric start/end time of an existing cue independently of Split;
- non-adjacent or multi-row merge;
- automatic transcript rewriting or retranscription;
- cloud confidence evaluation, telemetry, or a second model;
- displaying speaker confidence as transcript confidence;
- changing render style based on confidence;
- the bottom waveform; and
- rewriting old release evidence or immutable project artifacts.

this contract. Newly discovered technical constraints may change sequencing or
internal design, but any user-visible behavior, privacy boundary, release gate,
or out-of-scope item requires a documented scope revision before work continues.

added. The current native app already has Merge Next and Return-triggered

runner did not exit after that timeout and was interrupted. This is a

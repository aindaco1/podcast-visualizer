# Podcast Visualizer 1.2.1

Podcast Visualizer 1.2.1 fixes new-project creation for ordinary Finder-style
directory names and adds a private, user-controlled diagnostic export for
support.

## Safe project names with spaces

New projects can now use safe directory names containing interior spaces,
including the app's own `Podcast Visualizer Project` default. Names that are
empty, reserved, traversal-like, dot-prefixed, control-character-bearing, or
otherwise unsafe remain rejected before a project directory is created.

An unsafe name now returns the stable `project_name_unsafe` diagnostic code and
actionable private guidance. The selected source media is preserved and no
partial project is created.

## Private support diagnostics

The app toolbar now includes **Export Diagnostic Log**. It creates a local JSON
report that the user can review before manually sending it to support. Nothing
is uploaded automatically.

Reports use a strict, bounded schema and contain only app/system metadata,
workflow-stage transitions, command outcomes, durations, and stable diagnostic
codes. They exclude media and project paths, command arguments, transcript
text, speaker or review data, model inputs and outputs, rendered output, review
tokens and URLs, and raw helper output. The app rejects tampered, symlinked, or
non-regular log files and never replaces an existing export.

## Actionable native failures

Unexpected native-app failures no longer expose raw error descriptions. The
app explains that source media, project data, and completed stages were
preserved, provides a safe retry path, and points repeated failures to the
diagnostic export.

The updater delta for this release is generated from the verified 1.2.0 update
archive. No source podcast media, transcripts, model inputs, review data, or
project output is included in the release artifacts.

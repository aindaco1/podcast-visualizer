# Podcast Visualizer 1.2.0

Podcast Visualizer 1.2.0 adds automatic, locally generated episode chapters
with exact reviewed timestamps and an explicit approval gate.

## Grounded chapter suggestions

After transcript approval and alignment, the new **Chapters** tab can generate
topic-style or question-style chapter suggestions with Apple's on-device
Foundation Models framework on supported Macs. The model sees bounded reviewed
text windows and may choose only supplied alignment anchors. It never invents
timestamps, changes transcript text, identifies speakers, or sends podcast data
off the Mac.

Every suggestion remains editable. Approval requires at least three chapters,
starts at `00:00`, enforces YouTube's ten-second spacing rules, and resolves
timestamps from immutable word-alignment evidence. Manual editing remains
available when the system model is unavailable or its response is rejected.

## Reviewable local exports

Approved chapters export as paste-ready YouTube text, a Markdown table, or
structured JSON. Contexts, approvals, and exports are content-addressed and
immutable; explicit working-copy saves are atomic and preserve drafts associated
with older transcript or alignment revisions.

The implementation selectively adapts the topic/question, word-snapping,
re-analysis, and multi-format ideas from Craig Mod's MIT-licensed
[`youtube-timestamps`](https://github.com/cmod/youtube-timestamps) while retaining
Podcast Visualizer's offline Parakeet, WhisperX, shared timed-text, and native
Foundation Models stack. No hosted transcription or hosted LLM dependency was
added.

## Security and performance

Chapter contracts reject unknown fields, symlinks, traversal, stale identities,
non-canonical hashes, invented anchors, unsafe text, and tampered source
evidence. Failures state what was preserved and how to recover. Contexts and
subprocess output are bounded, and the shared linear planner has a 10,000-cue
performance regression gate.

The native app and packaged helper also share one top-level progress identity
for Transcript Review and Chapters subcommands, preventing a completed analysis
from being mistaken for invalid progress while entering review. If progress is
ever rejected, the app confirms that source media and completed stages remain
preserved and tells the user how to resume.

No source media, transcript, model input, review data, or project output is
included in the release artifacts.

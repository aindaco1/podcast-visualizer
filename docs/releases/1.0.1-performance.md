# Podcast Visualizer 1.0.1 performance evidence

Measured on Apple Silicon macOS on 2026-08-08. Figures are nine-run medians and
worst observed samples unless noted. Synthetic fixtures are deterministic and
contain no private transcript data.

## Transcript normalization and grouping

Run `node scripts/release/benchmark-transcript-pipeline.mjs` from the repository
root. The bounded grouping optimizer evaluates at most 16 candidate words per
position, so its complexity is O(n × 16).

| Synthetic duration | Words | Normalization median / worst | Grouping median / worst |
| --- | ---: | ---: | ---: |
| 5 minutes | 750 | 0.303 / 1.599 ms | 0.764 / 3.019 ms |
| 30 minutes | 4,500 | 1.718 / 2.095 ms | 3.474 / 4.422 ms |
| 120 minutes | 18,000 | 6.863 / 8.590 ms | 13.767 / 21.462 ms |

The 24× duration increase from 5 to 120 minutes remains linear and preserves
every timed word under the automated invariants.

## Transcript Review search and replacement

Build the release package first, then compile and run the standalone benchmark:

```bash
swift build --package-path macos -c release --disable-automatic-resolution
xcrun swiftc -O \
  -I macos/.build/arm64-apple-macosx/release/Modules \
  scripts/release/benchmark-transcript-search.swift \
  macos/.build/arm64-apple-macosx/release/PodcastVisualizerCore.build/*.swift.o \
  -o /tmp/podcast-visualizer-benchmark-transcript-search
/tmp/podcast-visualizer-benchmark-transcript-search
```

On 10,000 cues with 100 literal phrase matches:

| Operation | Median | Worst |
| --- | ---: | ---: |
| Build literal match index | 4.782 ms | 8.108 ms |
| Validate and replace selected match | 5.964 ms | 6.255 ms |
| Replace all 100 matches | 6.100 ms | 6.128 ms |
| Navigate 100,000 times | 0.533 ms | 0.536 ms |

The single-cue UI selection and scrolling layer consumes the stable cue ID and
UTF-16 range produced by this bounded pass; speaker-only changes do not mutate
cue text.

## Alignment-only runtime

The same representative 87-second proof and pinned Wav2Vec2 model were aligned
with the original and optimized environments. Both produced exactly 222
candidate words and zero projection issues.

| Runtime | Wall time | Peak RSS |
| --- | ---: | ---: |
| 1.0.0 dependency closure | 0.509 min | 1,436.734 MB |
| 1.0.1 alignment-only closure | 0.525 min | 1,300.031 MB |

The alignment-only result is 3.1% slower in this sample and uses 9.5% less peak
memory. This is within the release regression budget and retains deterministic
word projection and the offline socket guard.

## Streaming render

An isolated copy of the existing 87-second proof was rendered as Landscape
16:9 opaque H.264 with the current release code. No existing project stage or
output was changed.

| Measurement | Result |
| --- | ---: |
| Wall time | 18.36 s |
| Peak RSS | 198,656,000 bytes |
| Output duration | 89.000 s including the 2 s title lead-in |
| Video/audio duration difference | 0.000 s |
| Video frames | 2,136 at 24 fps |

The renderer streamed directly into the final MP4 and created no image-sequence
intermediate. Its seven still images were the bounded technical-QC frames
already required by the render contract.

The Developer ID-signed helper binaries use sandbox inheritance and therefore
must be exercised as children of the signed app for the final installed smoke
test. The isolated timing run used the same verified pre-sign runtime payload;
final CI separately verifies every signed nested binary and entitlement.

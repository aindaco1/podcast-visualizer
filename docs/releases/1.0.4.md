# Podcast Visualizer 1.0.4 (unreleased)

Podcast Visualizer 1.0.4 makes first-run model setup discoverable and removes
GitHub's Node 20 action-runtime deprecation notice. Project, transcript, render,
and model formats do not change.

## Model setup

- The Models card lists every active search location instead of requiring users
  to guess where a model folder lives.
- App storage and Downloads are checked automatically. Development builds also
  show the exact repository model root they use.
- Users may add up to eight additional folders. The app stores read-only
  security-scoped bookmarks and checks only the exact pinned model folder names;
  it does not enumerate or index unrelated files.
- A verified Parakeet or alignment copy found in a search location is imported
  automatically into persistent app-owned storage.
- Missing models expose **Download** and **Import Existing…** actions together
  with their publisher, download size, and license.

Network downloads never begin automatically. The confirmation identifies the
publisher, license, and size and states that no media or transcripts are
uploaded. The downloader permits only pinned HTTPS sources and approved
redirect hosts, enforces a 1 GiB total safety bound, streams into a private
staging directory with measured progress, checks every size and SHA-256, runs
the existing model verifier, and installs with one atomic rename. Cancellation,
network failure, invalid redirects, over-size responses, checksum failures, and
verification failures leave the prior installation unchanged.

## GitHub Actions

- `actions/checkout` is pinned to `v7.0.1` commit
  `3d3c42e5aac5ba805825da76410c181273ba90b1`.
- `actions/setup-node` is pinned to `v7.0.0` commit
  `820762786026740c76f36085b0efc47a31fe5020`.
- `astral-sh/setup-uv` is pinned to `v9.0.0` commit
  `c771a70e6277c0a99b617c7a806ffedaca235ff9`.

Each action declares the Node 24 runtime at that exact commit. setup-uv v9
changes its cache-pruning default, so the workflows explicitly retain
`prune-cache: true` to preserve the previous storage behavior. Provenance
attestation remains on the already-current composite action pin.

## Release validation

The 1.0.4 release workflow uses the checksum-pinned public 1.0.3 ZIP as its
Sparkle delta base. Required gates cover automatic candidate selection,
security-scoped bookmark persistence, symlink rejection, atomic import and
download behavior, redirect and checksum failures, bounded progress, exact
cross-language Parakeet manifest synchronization, reviewed sandbox
entitlements, Node 24 action pins, and the existing full Swift, JavaScript,
alignment, timed-text, signing, notarization, SBOM, and size-budget suites.

# Podcast Visualizer 1.2.4

Podcast Visualizer 1.2.4 corrects reviewed-speaker presentation, restores the
current transcript summary when reopening a project, and reduces duplicated
application policy without changing project, transcript, scene, or render
formats.

## Reviewed speaker status

The Transcript card no longer labels every analysis-time speaker cluster as
anonymous after a human has named it. Browser and native approval now return
one shared, bounded transcript summary containing word, cue, speaker, and
recognized-speaker counts. `status` derives the same summary from the validated
active approved revision, so approved, aligned, and verified projects retain
the correct presentation after relaunch.

Stable `speaker-NN` values remain anonymous acoustic identities. A speaker is
reported as recognized only when its reviewed display name differs from the
default `Speaker N` label. Mixed and legacy revisions remain explicit rather
than inventing recognition.

## DRY maintenance pass

- One project-stage inspection now supplies both the resumable state and the
  validated active transcript instead of resolving them independently.
- Browser and native review approvals use one result builder.
- Transcript summary wording is owned by one typed Swift contract instead of
  being assembled inside the view.
- Transcript, chapter, and branding edits use one private temporary-file
  staging policy while retaining their separate size bounds and
  preservation-focused recovery messages.

The complete audit and intentionally deferred seams are documented in
[`../testing/1.2.4-dry-audit.md`](../testing/1.2.4-dry-audit.md).

## Regression coverage

Coverage includes anonymous, recognized, mixed, and legacy speaker summaries;
the review-gated new-project workflow; resumable project opening; post-render
transcript revision invalidation; explicit rerender; export; cancellation; and
private-edit failure presentation. The maintained flow matrix is in
[`../testing/user-flow-regressions.md`](../testing/user-flow-regressions.md).

## Privacy and compatibility

All summary data is read from existing validated local project artifacts.
Media, transcripts, display names, review data, and model inputs remain on the
Mac. Existing project files and generated stages are not rewritten. The app
continues to target Apple Silicon and macOS 15 or later, and Sparkle update
installation remains user approved.

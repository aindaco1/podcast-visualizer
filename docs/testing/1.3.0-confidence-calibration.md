# Podcast Visualizer 1.3.0 confidence calibration

Status: initial release calibration passed on 2026-09-01.

Recognition confidence is an advisory review-queue signal, not a correctness
guarantee. The native UI exposes only **Ultra Low**, **Low**, **Medium**,
**High**, or **Unavailable**. It never displays the underlying token score.
Speaker/diarization confidence is separate and is never presented as transcript
confidence.

## Method

`npm run confidence:calibrate -- --project /absolute/project` reads only
validated, local `speech.json`, draft, and saved working or approved transcript
artifacts. It compares normalized spoken words while ignoring capitalization,
punctuation, formatting, speaker assignment, and timing-only changes. Projects
whose cue identities or timing changed are rejected so structural edits cannot
be mislabeled as recognition errors.

The report contains aggregate counts and rates only. It emits no project path,
transcript text, token text, speaker name, audio, or model input. Private source
artifacts remain outside Git and CI.

Policy `parakeet-spoken-token-minimum-v1` associates spoken tokens to cues by
maximum timing overlap and assigns the cue its least-confident contributing
token. Fixed boundaries are `<0.50` Ultra Low, `<0.90` Low, `<0.98` Medium,
and otherwise High. Missing valid token coverage is Unavailable.

## Observed evidence

Two rights-cleared local projects contributed 180 reviewed cues. The set had
an average of 10.68 spoken words and 3.518 seconds per cue; maxima were 17 words
and 6.960 seconds. Only aggregate evidence is recorded here.

| Tier | Cues | Spoken-word corrections | Observed correction rate |
|---|---:|---:|---:|
| Ultra Low | 22 | 0 | 0.0% |
| Low | 87 | 2 | 2.3% |
| Medium | 33 | 0 | 0.0% |
| High | 38 | 0 | 0.0% |

Ultra Low + Low contained 109 of 180 cues (60.56%) and both observed
spoken-word correction cues (100% observed recall). No observed correction
landed in Medium or High. The priority queue therefore removed 39.44% of cues
from first-pass review while retaining every observed recognition error.

This is a deliberately conservative first-release policy and a small-error
sample. The result supports useful triage but does not establish that Medium or
High text is correct. The UI and release notes preserve that limitation. Future
calibration can add local reviewed projects through the same aggregate-only
tool; changing boundaries requires a new policy version and regression fixture.

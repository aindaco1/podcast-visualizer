# Podcast Visualizer 1.2.4 DRY audit

This audit covers the native app, typed CLI boundary, local review flow,
project-state restoration, tests, and release metadata. It is a
behavior-preserving maintenance pass, not a visual redesign or a change to the
media pipeline.

## Consolidated in 1.2.4

| Area | Prior duplication or drift | 1.2.4 owner |
|---|---|---|
| Transcript card | The view labeled the analysis count as anonymous at every later stage | `TranscriptSummary.presentation` |
| Project reopen | Stage detection and active transcript summary would otherwise require separate resolution | `inspectProjectStage` |
| Review approval | Browser and native commands assembled parallel result objects | `approvedReviewResult` |
| Private edits | Transcript, chapters, and branding repeated directory, permission, encoding, collision, and cleanup logic | `PrivateEditKind` plus `makePrivateEdit` |
| Flow coverage | State, CLI, and view-contract tests existed but had no maintained user-flow index | `user-flow-regressions.md` |

These seams are intentionally narrow. JavaScript remains authoritative for
validated project evidence, while Swift owns typed presentation and workflow
orchestration.

## Reviewed and retained

- Generic timing, reflow, alignment, and chapter logic already lives in the
  shared timed-text package. Moving application policy there would weaken the
  repository boundary, so no further extraction was made.
- CLI fixtures and the demo client deliberately repeat external contract
  examples. They are independent compatibility witnesses, not production
  implementations to merge.
- Release version assertions appear in several gates on purpose. They prevent
  a tag, plist, package, release note, SBOM, and delta base from drifting.
- Security and preservation checks stay close to each trust boundary even when
  their shapes look similar; traversal, symlink, bounded-output, and immutable
  stage rules were not generalized away.

## Deferred maintainability opportunities

1. `AppStore` remains the largest native file and coordinates project,
   transcript, chapter, branding, model, render, and diagnostic flows. Future
   feature work should extract one actor or coordinator at a time only when an
   exercised flow can remain unchanged. A broad file split in this maintenance
   release would add regression risk without changing behavior.
2. Transcript and chapter stores have parallel dirty/save/approve concepts,
   but their validation and lifecycle rules differ materially. Keep their
   domain state separate; share only proven transport helpers.
3. Release documentation has historical repetition. Preserve immutable release
   records and add new summaries rather than rewriting old evidence into a
   generated document.

No user project, media, model, approved transcript, scene, render, or review
working copy is changed by this audit.

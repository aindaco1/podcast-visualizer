# Podcast Visualizer 1.3.0 transcript-review performance baseline

Measured 2026-09-01 on the release development Apple Silicon Mac with Node 24
and the macOS 15 deployment target. Tests use synthetic text and do not contain
private podcast content.

The shared confidence compiler was warmed once and measured over six retained
runs. Each synthetic cue had one spoken token.

| Cues | Median compile time | Serialized confidence bytes |
|---:|---:|---:|
| 100 | 0.306 ms | 13,166 |
| 1,000 | 1.340 ms | 131,967 |
| 10,000 | 15.055 ms | 1,337,968 |

The committed maximum-size shared-package test completed in 25.06 ms including
fixture setup and assertions. A second adversarial case with 10,000 tokens that
each spans all 10,000 cues completed in 11.22 ms using the bounded range index;
it does not rescan the cue array per token. The native 10,000-cue confidence
filter test completed inside a 0.73-second nine-test suite and returned 5,000
matching cues in chronological order. The store uses one cue-ID index and one
confidence-tier index, so filtering is one bounded pass rather than a per-row
search.

Native workspace responses retain split-specific token timing evidence through
20,000 spoken tokens. Above that bound the cue tier and internal aggregate score
remain available, but per-token split evidence is omitted; split children then
inherit the parent tier conservatively. This keeps the existing four-megabyte
app subprocess-output boundary safe for long transcripts.

The initial unoptimized development alignment runtime described 31,364 files
and 979,430,596 logical bytes; 9,480 generated entries had been evicted by
CloudDocs, causing transient read timeouts. The checksum-pinned restore removed
unused alignment packages and produced the release-shaped v2 runtime: 7,097
files, 432,648,430 bytes, and no dataless entries. Its exact manifest validation
completed in 0.75–0.89 seconds and the full runtime suite, including all bundled
encoders, completed in 3.80–4.72 seconds.

Runtime-tree hashing uses eight bounded readers, retries only `EAGAIN`, `EBUSY`,
and `ETIMEDOUT` up to three attempts, and folds completed hashes into the digest
in canonical path order. Tests prove out-of-order completion is byte-identical
and permanent errors still fail immediately. The runtime test retains a finite
five-minute ceiling for slower release hosts.

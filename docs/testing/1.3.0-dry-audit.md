# Podcast Visualizer 1.3.0 DRY audit

## Shared ownership

| Concern | Single owner |
|---|---|
| Spoken-token association, aggregation, tier boundaries | `@dustwave/timed-text/confidence` |
| Untrusted edit validation, persistence, lineage, derived evidence | JavaScript review workspace |
| Pure Unicode-safe split and adjacent merge policy | `PodcastVisualizerCore.ReviewEditing` |
| Dirty state, Undo, filters, Checked state, rename commits | `TranscriptReviewStore` |
| Labels, focus, selection, and actions | `TranscriptReviewView` |

The browser fallback intentionally keeps its proportional split interaction,
but submits to the same canonical JavaScript validator. It allocates stable cue
IDs without a million-item temporary array and preserves Checked state only for
unchanged cues.

Swift and JavaScript both validate the typed workspace at their trust
boundaries. That duplication is intentional defense; mutation and threshold
policy are not duplicated. Recognition evidence is derived from immutable local
speech analysis and cannot be submitted by a client, enter approved transcript
hashes, or influence renders.
